# CLAUDE.md — delta-one (Rust)

Delta One engine: linear hedging, firm-wide netting, execution, and the three outbound planes (NATS, FIX 4.4, Kafka). Latency-sensitive. Read the root `CLAUDE.md` first; invariants there apply here.

## Crate layout (Cargo workspace)

| Crate            | Role | Hot path? |
|------------------|------|-----------|
| `d1`             | process binary: owns the core thread (`OrderStore` + `PositionKeeper`) and starts the gateways, wired together over `rtrb` rings (ADR-013) | no (hosts the hot path) |
| `d1-core`        | market-data ingest, position keeper (incl. per-book cash, ADR-010), order state machine, risk checks | **yes** |
| `d1-netting`     | firm-wide netting across books, internal-cross generation (ADR-005) | **yes** |
| `d1-gateway-nats`| NATS in/out: consume EXO targets + UI commands, publish exec reports & risk | no |
| `d1-gateway-fix` | FIX 4.4 session + message build/parse via `quickfix` crate (ADR-003) | edge |
| `d1-posttrade`   | Kafka producer, Avro encoding, booking events (ADR-002) | no |
| `d1-analytics`   | tracker analytics: ex-post TE, tracking difference, cash drag (ADR-010); runs on the core thread at each sampling boundary (2 × `te_window_obs` `i128` ops per book plus a `println!` per sampled book); off the benchmarked tick→order path | no |
| `d1-refdata`     | loads `protocol/refdata/universe.json` into the keeper/market-data universe + cross-price policy at startup; keeps `d1-core` JSON-free | no |

Threading model: one pinned thread per hot-path stage, communicating over bounded SPSC ring buffers, `rtrb` for every ring (ADR-013 — bounded `crossbeam-channel` rejected, its blocking ops lock and it's MPMC machinery this project never needs). Gateways run on separate threads/tokio runtimes and exchange data with the core only through those queues. The core never awaits. `rtrb` has no disconnect signal, so ring shutdown is an explicit `AtomicBool` flag checked each poll-loop iteration, not channel-close semantics.

**M3 status:** P1.M3 Slice 2 (netting wiring) and Slice 3 (crosses & directed transfers, `feat/d1-crosses-transfers`) are both complete. `crates/d1`'s core thread (shared between the binary and its integration tests via `crates/d1/src/lib.rs::spawn`) now drains 8 `rtrb` rings: the Slice 2 FIX pair (outbound `Order`, inbound `ExecEvent`), inbound `Target` and outbound `ExecReport` to/from `d1-gateway-nats` (added when the NATS plane landed), the feed-ingest ring (`FeedTick`), Slice 3's outbound `CrossRecord` / inbound `TransferRequest` pair, and (P1.M4 Slice 2) the outbound `PostTradeEvent` ring feeding the `d1-posttrade` Kafka producer thread. `crates/d1/src/feed.rs` is a synthetic producer thread — no real market-data transport exists yet, `sim.md.<instrument>` on NATS is UI-display-only (`protocol/nats-subjects.md`). Targets flow through `NettingSession::on_target` (in `delta-one/crates/d1/src/cycle.rs`), computing per-book demand as `target_b − position_b − inflight_b`, firm-wide netting via `d1_netting::net`, and a single firm-level external `Order { book: BookId(0) }` for the net residual, with fills allocated pro-rata back to books. Internal crosses (netting-derived and directed-transfer, both booked through the shared `cycle::book_cross` helper, ADR-009) are published as `InternalCrossNotice` on NATS `d1.crosses`, each stamped with a `cross_id` (UUIDv7) minted at booking time — the compliance-lineage key the Kafka `posttrade.crosses` record (wired in P1.M4 Slice 2) shares. `NettingSession::on_transfer` consumes `InternalTransferRequest` from `exo.transfers.<book>`, validated against the keeper's universe by `run_core` before booking (root invariant #2), and books immediately with no external order or parent-order tracking. The CLI startup order is retained as a FIX round-trip anchor.

**M4 status:** P1.M4 Slice 3 (deterministic golden-file e2e, `feat/d1-deterministic-golden-file`) is complete. The `Stamper` enum (`Wall` | `Fixed { next }`) seams UUID and timestamp minting in `d1-posttrade::convert`, allowing reproducible `msg_id`/`booked_ns`/`ts_ns` in golden output; deterministic mode is a `d1::spawn` library parameter only (the originally-planned `--deterministic` CLI flag was rejected on security review: fixed `msg_id`s restart at 1 each process start, violating root invariant #4's dedupe guarantee). `ExecOutcome { Duplicate, Applied(Option<Fill>) }` replaces the ambiguous `Option<Fill>` to properly wire non-fill terminal audits (reject/cancel/expire) to `posttrade.orders.audit`. The synthetic feed now ticks every instrument in the keeper universe, and `run_core` primes `MarketData` synchronously at t=0, preventing `arrival_mid_px_e9` from returning `0` on first tick. The `posttrade.*` topics are provisioned out-of-band via `scripts/demo.sh` (compose disables auto-create); the producer hard-errors at startup if any topic is missing. Ordered shutdown is now a contract, because the core and the producer form a pipeline and signalling both at once lets the drain side exit while the pusher is still feeding it: signal the core's shutdown flag, join the core thread (the *only* pusher onto the `PostTradeEvent` ring, so joining it means no further pushes are possible), then signal `posttrade_shutdown` and join the producer thread — whose one final `drain()` after observing that flag is therefore provably complete rather than best-effort. `just demo` runs three round-trip tests (`nats_round_trip`, `crosses_round_trip`, `golden_posttrade`); the last asserts the four `posttrade.*` topics byte-for-byte against committed fixtures in `sim/golden/`, and `UPDATE_GOLDEN=1` regenerates them. **Confluent Schema Registry framing (ADR-002) landed after Slice 3**, closing a gap where the producer published raw Avro datums: `d1-posttrade::registry` registers all four schemas under `<topic>-value` at producer startup (idempotent, and the same subjects `scripts/schema-check.sh` gates in CI), caches the ids, and prefixes every payload with `0x00 || schema_id BE32`. Broker address and registry URL now travel together as `PostTradeConfig` (`d1::spawn`'s `posttrade_cfg`), making "Kafka without a registry" unconstructable; a registry failure kills the producer thread the same way a missing topic does — logged immediately, process keeps running. The golden fixtures store *decoded* JSON and were unchanged by this work, which is what makes them an independent check that framing left the datum intact.

Two consumer-side guards in `crates/d1/src/lib.rs::run_core` are load-bearing, not incidental: (1) `exo.targets.>` is a wildcard, so a target may name a (book, instrument) this process has no keeper slot for — those are **rejected**, because placing the order would fill at the venue with nowhere to book the position (root invariant #2), and (2) `d1-gateway-nats` dedupes inbound `TargetPosition` on `Meta.msg_id` (root invariant #4), mirroring `OrderStore`'s `ExecId` dedupe on the FIX side. As of P1.M3 Slice 1, the keeper/market-data universe comes from `protocol/refdata/universe.json` via `d1-refdata` at startup (not just the CLI startup order's book/instrument), so guard (1) now meaningfully rejects only pairs outside universe.json — every in-universe pair, whether or not it's the CLI startup pair, gets a keeper slot. The CLI startup order remains additive alongside NATS-driven targets; excising it is future work.

**M5 status:** P1.M5 (tracker analytics, `feat/d1-tracker-analytics`) is complete across all three slices. `d1-analytics` is a standalone crate (depended on by both `crates/d1` for sampling-loop integration and `d1-posttrade` for Avro encoding of the daily record) with zero transitive dependencies aside from `d1-core` for the `BookId` newtype; the crate implements pure integer-only mathematics with strict width discipline (`i128`/`u128` accumulators throughout, narrowing to `i64` only at output via `checked_` arithmetic), no floats, and no allocations beyond the one pre-sized `VecDeque` per window. `PositionKeeper` now tracks per-**book** cash: seeded from refdata's `initial_cash_e9` per tracker book at startup, moved on every fill (buy pays, sell receives), credited on a dividend tick via `credit_dividend` (all-or-nothing across books via two passes, no allocation), and grown once per sample by `accrue_cash` — the yield must actually accrue, or cash earns 0 in NAV while ADR-010's drag formula assumes otherwise. The atomicity refactor is what preserves `apply_cross`: `slot()` now returns `(book_idx, position_slot)` and `compute_fill()` returns the new **absolute** cash value alongside the new `Position`, so both legs are still computed against current state before either is committed. Its disjointness argument extends unchanged rather than needing a second check — the instrument is shared between legs, so `buy_slot == sell_slot` iff `buy_book_idx == sell_book_idx`, and `book_idx` is exactly the index into `cash_e9`. The cash delta is computed in `i128` (`qty_e2 · px_e9` reaches ~9e30) and narrowed with a checked cast, but divides by 100 on an `i64` fast path: LLVM lowers `i128 / 100` to a `__divti3` libcall rather than multiply-by-reciprocal, which cost 94ns per fill. Both arms divide the same value under the same truncation-toward-zero rule, so they are bit-exact — and that symmetry is also what makes a buy plus its inverse sell restore cash exactly and a cross's two legs sum to zero firm cash. `PositionKeeper::apply_fill` regressed from 15.79ns → 23.36ns on the `m2s1` release baseline (`MarketData::ingest` +32% over same baseline, so genuine added cost ~2-3ns net); the hot-path bench gate remains 10–50 µs T2T. `d1-refdata::Universe` parses and validates all tracker-book benchmarks: existence, constituent resolution, weight positivity, deduplication, sum-to-1.0e9 normalization, and benchmark symbol quotability (all fail-loud at startup). `crates/d1/src/config.rs` parses `[tracker]` from `d1.toml` with range-validated knobs (`sampling_interval_s > 0`, `te_window_obs 2–10,000`, `publish_interval_s` parsed but not yet separate from sampling cadence). The core thread samples at each `sampling_interval_s` boundary (synthetic feed clock, deterministic), reads the keeper and market-data snapshots to compute book NAV + benchmark returns (fixed-weight `Σ w_c · r_c`), and publishes `TrackerAnalytics` (Protobuf) on `d1.tracker.<book>` via NATS. The Kafka record is emitted **once per tracker book, after `run_core`'s drain loop exits** — ADR-010 §4's "daily" record read as end-of-session, since this process never sees an EOD boundary, so `publish_interval_s` governs only the NATS cadence. That placement is also load-bearing for determinism: `rtrb` is FIFO and the ordered-shutdown contract joins `core` before signalling the producer, so the push is provably both last-in-stream and still drained, whereas a mid-stream insert would shift every `msg_id` in the `Stamper::Fixed` sequence and force all four existing fixtures to be regenerated. `as_of_ns` is deliberately `window_end_ns` (from the synthetic feed clock), never `Stamper::now_ns`, which is a *constant* in deterministic mode and would collapse the window to zero length. The golden test therefore gained **no fifth fixture** — `n_obs` depends on real handshake timing, so a byte-diff would be permanently flaky — and instead asserts the single record by property, synchronising on a bounded poll of `d1.tracker.1`. The four existing golden Avro fixtures remain byte-identical, which is the independent proof the ordering works.

## The hot path contract (tick → order emit)

Target: 10–50 µs T2T inside the process, measured p50/p99/p99.9 with `criterion` + HDR histograms on a **release build** with pinned cores. Rules on any code reachable from the hot path:

1. **No heap allocation.** No `Box`, `Vec::push` beyond pre-reserved capacity, `String`, `format!`, or `clone()` of owning types. Pre-allocate at startup; use fixed-size arrays, arenas, or object pools. If you think you need an allocation, you need a design change.
2. **No locks.** No `Mutex`, `RwLock`, no `.lock()`. SPSC queues and single-writer state only. `Atomic*` with explicit ordering is allowed and must carry a comment justifying the ordering.
3. **No syscalls / no I/O / no logging.** Telemetry = write a fixed-size event into a preallocated ring consumed by a slow-path thread.
4. **No `async`.** Hot path is a poll loop (busy-spin or `spin_loop` hint).
5. **No panics.** `unwrap()`, `expect()`, `panic!`, indexing with `[]`, `unreachable!` are banned outside `#[cfg(test)]`. Use pattern matching and `get()`; unrepresentable states should be unconstructable via types.
6. **No `unsafe`** anywhere in this workspace without a dedicated ADR and a `// SAFETY:` comment. (The `quickfix` crate wraps C++ internally; that is confined to `d1-gateway-fix` and is off the hot path.)
7. **No floating point for money.** `price_e9: i64`, `qty_e2: i64` as defined in `protocol/proto/common.proto`. Overflow-checked arithmetic (`checked_add` etc.) at boundaries; `debug_assert!` internal invariants.

Enforcement: `cargo clippy` with `-D warnings` plus the lint set in `Cargo.toml` (`unwrap_used`, `expect_used`, `panic`, `indexing_slicing`, `float_arithmetic` allowed only in clearly marked non-hot modules).

## Rust guardrails for newcomers (this team is new to Rust)

- **Don't fight the borrow checker with `clone()` or `Rc<RefCell<..>>`.** If ownership is unclear, restructure: single owner, pass `&`/`&mut` down. Ask for a design review comment in the PR instead of sprinkling `clone()`.
- Prefer plain `struct` + `enum` + `match`. Avoid trait objects (`dyn Trait`) and generics-heavy designs until profiling or reuse demands them.
- `thiserror` for library errors, one error enum per crate; `anyhow` only in binaries. Never stringly-typed errors.
- Newtypes for identifiers: `BookId(u32)`, `InstrumentId(u32)`, `ClOrdId([u8; 20])`. Never pass bare `u32`/`&str` across module boundaries.
- All public items get `///` docs; `#![deny(missing_docs)]` on library crates.
- Tests live next to code (`#[cfg(test)] mod tests`); property tests with `proptest` for netting and order-state-machine logic are mandatory (netting bugs are silent money-losers).
- If a lifetime annotation gets complicated, stop and simplify the design. Complexity budget is spent on latency, not on clever generics.

## Netting & internal crosses (summary — full spec in ADR-005)

- Inputs: per-book target positions (from EXO via NATS, and Delta One's own index-tracking targets), current per-book positions, in-flight orders.
- Per instrument: `net_external = Σ_book (target_book − position_book − inflight_book)`.
- The offsetting portion across books is booked as **explicit internal crosses**: two internal trades (one per book side) at the cross reference price, published to Kafka as `InternalCross` events, plus one external order for the residual. Worked example (verified): D1 book target +1,000,000 AAPL, EXO book target −800,000 → internal cross 800,000 (D1 buys from EXO internally, both legs booked), external order 200,000 buy.
- Cross reference price policy is configurable per instrument class (arrival mid default); it is a compliance-visible parameter, never hardcoded.
- External fills are allocated back to books pro-rata to residual demand; allocation events go to Kafka with full lineage (`parent ClOrdID`, fills, cross ids).

## Outbound planes

1. **NATS** (`d1-gateway-nats`): publish `ExecutionReport`, `PositionSnapshot`, `RiskSnapshot` (Protobuf) on subjects in `protocol/nats-subjects.md`; consume `TargetPosition` from EXO and `Command` request/reply from UI.
2. **FIX 4.4** (`d1-gateway-fix`): `NewOrderSingle` (35=D), `ExecutionReport` (35=8) inbound, `OrderCancelRequest` (35=F), `OrderCancelReplaceRequest` (35=G). Standard FIX 4.4 semantics only in Phase 1; venue dialects (EMSX/TSOX/FXAll) are thin adapter modules added later — their specs are proprietary and need firm entitlements, so the demo runs against `sim/`'s QuickFIX acceptor.
3. **Risk limits (Tier-1, ADR-008):** aggregate own delta with EXO-published Greeks per underlying, check against `d1.toml` limits (config, never code), publish `RiskLimitAlert` on `d1.alerts.limits`. Off hot path. Never auto-trades options on breach.
4. **Proposals & directed transfers (ADR-009):** cache active `HedgeProposal`s; on `ProposalDecision` validate (known, unexpired, same risk checks as any flow) then execute legs as ordinary orders for the proposing book; audit rejects with reason. `InternalTransferRequest` books a directed cross via `d1-netting`'s instruction entry point — same booking path, reference-price policy and records as netting-generated crosses.
5. **Kafka** (`d1-posttrade`): topics `posttrade.trades`, `posttrade.crosses`, `posttrade.allocations`, `posttrade.orders.audit`, `posttrade.tracker.analytics` (daily record, ADR-010) — Avro, Schema Registry, keyed by instrument for `trades` and by `cross_id` for crosses. Every payload is Confluent-framed (`0x00` + big-endian schema id + datum, `d1-posttrade::registry`); the producer registers all five schemas at startup and hard-errors if the registry is unreachable, because an unframed record is undecodable by any consumer that does not already know the writer schema. At-least-once producer with idempotence enabled; consumers dedupe on `msg_id`.

## Definition of done for any delta-one PR

- clippy/fmt/tests green; no new lint allows.
- If the change touches `d1-core` or `d1-netting`: criterion bench diff pasted into the PR (p50/p99), and a proptest covering the new behavior.
- If the change touches a wire format: ADR + `just schema-check` green.
