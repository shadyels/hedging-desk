# scripts/

- `gen-proto.sh`   — protoc → prost (Rust), protobuf (Python), ts-proto (TS), all via local plugin binaries (ADR-012). Outputs are committed.
- `schema-check.sh`— proto append-only lint (buf breaking) + Avro BACKWARD compatibility vs Schema Registry. P1.M5 put the first *real* evolution through it: `tracker_analytics.avsc` gained `sampling_interval_s` with a default (additive, BACKWARD-compatible), and the avsc→subject table already mapped `posttrade.tracker.analytics`. The avsc→topic table is a `case` statement rather than a `declare -A` associative array specifically because macOS ships bash 3.2.57, which has no `declare -A`; `just schema-check` runs on a stock Mac as a result. The CI gate uses `.github/workflows/schema-compat.yml` on `ubuntu-latest` (bash 5.x) regardless.
- `demo.sh`        — P1.M2 slice 3 (docs/ROADMAP.md): `just up`, wait for NATS, run `cargo test -p d1 --test nats_round_trip -- --ignored --nocapture` (publishes a `TargetPosition`, asserts an `ExecutionReport` reaching `Filled` comes back over real NATS + FIX). P1.M3 slice 3 added `cargo test -p d1 --test crosses_round_trip -- --ignored --nocapture` (two opposite `TargetPosition`s cross internally, asserting an `InternalCrossNotice` on `d1.crosses` plus a residual `ExecutionReport`; then an `InternalTransferRequest` books a directed cross the same way). P1.M4 slice 3 added a Kafka-readiness wait, provisioning of the `posttrade.*` topics (four then; **five** since P1.M5 added `posttrade.tracker.analytics`) (`kafka-topics.sh --create --if-not-exists --partitions 1 --replication-factor 1`, done **before** the first `cargo test` above purely to provision once up front — only `golden_posttrade` actually wires a Kafka broker into `d1::spawn` and hard-errors at startup on a missing topic since `deploy/docker-compose.yml` disables auto-create; `nats_round_trip`/`crosses_round_trip` pass `kafka_brokers: None` and never touch Kafka), then `cargo test -p d1 --test golden_posttrade -- --ignored --nocapture` (drives the same crosses/transfers storyline with the Kafka broker wired in and `deterministic: true`, then diffs the resulting `posttrade.*` Avro records — decoded to JSON — against the committed golden files in `sim/golden/`; `UPDATE_GOLDEN=1` rewrites them instead of asserting). P1.M5 extended that same test with tracker analytics: it now also asserts exactly one Confluent-framed record on `posttrade.tracker.analytics`, by **property** rather than byte-diff (`n_obs` depends on real handshake timing, so a fifth fixture would be permanently flaky), synchronising on a bounded poll of NATS `d1.tracker.1` rather than a wall-clock floor. The four pre-existing fixtures must still match with no `UPDATE_GOLDEN` — that is the proof the end-of-loop Kafka push kept the `Stamper::Fixed` ordering intact. Then `just down` (see "Runs everything" below). Exits non-zero if NATS/Kafka never comes up or any of the four round trips fails. P2.M4 slice 5 added a fourth step, `cargo test -p d1 --test storyline -- --ignored --nocapture` (`just storyline`): the sim `tracker-flow` scenario drives `d1` and a real EXO process through the full loop (EXO initial hedge, gap, re-published targets, internal cross, residual order over FIX, dividend, tracker analytics). **Prerequisites:** the Docker daemon (`just up`, for NATS) and `uv` with a synced `exo/.venv` (the test spawns EXO via `uv run python -m exo`). The bus must be quiet: the test refuses to start if it sees other EXO/D1 traffic, so never run it concurrently with the other infra tests, `just exo` or `just d1*`. Exits non-zero like the other round trips. Deferred, not implemented here: leaving the UI running (Phase 3) — not pretended done.

**Runs everything (infra CI parity).** `demo.sh` now runs all six infra tests, strictly sequentially, in this order: `nats_round_trip`, `crosses_round_trip`, `loop_round_trip`, `golden_posttrade`, `storyline`, then the exo bus test (`cd exo && uv run pytest -m infra`, i.e. `exo/tests/test_bus_integration.py`). The Avro half of `schema-check.sh` is deliberately *not* repeated: `.github/workflows/schema-compat.yml` already runs it against a live registry. `demo.sh` exports `INFRA_REQUIRED=1`: each infra test normally *skips* (and a skip counts as a pass) when NATS/Kafka/Schema Registry is unreachable; with `INFRA_REQUIRED=1` that is a hard failure (Rust: `delta-one/crates/d1/tests/common/mod.rs`; Python: the autouse fixture in `exo/tests/test_bus_integration.py`). Unset, behaviour is unchanged, so a bare `cargo test -- --ignored` without `just up` stays harmless. A `trap` runs `just down` on every exit path; on failure the `docker compose logs` are printed first, since `down -v` destroys them (this replaces the earlier "containers left up for postmortem").

Run locally: Docker daemon running, `uv` installed and `cd exo && uv sync --all-extras --dev` done once, then `just demo` (or `./scripts/demo.sh`). **Never run infra tests concurrently with each other, or alongside `just exo` / `just d1*` / `just storyline` / a stack already up from elsewhere:** they share one NATS broker and subject namespace and the storyline refuses to start on foreign traffic.

CI: `.github/workflows/infra.yml` runs `./scripts/demo.sh` on `pull_request` to `main`, nightly (`schedule`) and `workflow_dispatch`, `timeout-minutes: 40`, with `INFRA_REQUIRED=1`. It is advisory by default: making it a *required* status check is a GitHub branch-protection setting, not repo config, so enable it there once it has proven stable.

### Manual storyline path

Same stack, by hand, in separate terminals: `just up`; `just sim-acceptor partial` (`fill_model` is a positional recipe arg — `fill_model=partial` would be passed through literally); `just d1-scenario` (replays `sim/scenarios/tracker-flow.yaml` with `delta-one/d1.scenario.toml`); `just exo`. Then watch the initial hedge with `nats sub 'exo.targets.3.>'`, `nats sub d1.marks.1001`, `nats sub d1.positions.3`. The manual path has **no `tracker_flow`** (only the `storyline` test harness publishes it), so no internal cross appears manually — expected. `just exo` runs `exo.toml` as committed (`[provenance] allow_dirty = false`), so on a dirty git tree EXO refuses to publish (`exo.health` `detail["publish"]` says `refused: dirty tree`) and NO initial hedge appears: commit first, or set `EXO_GIT_SHA=<7-40 hex chars>` (an operator assertion, used verbatim as the provenance sha and stamped on every published number; a `-dirty` suffix is still refused), or run EXO on a copy of `exo/exo.toml` with `allow_dirty = true` (what the storyline test does). `just down` when finished.

`gen-proto.sh`/`schema-check.sh` are implemented in P1.M1; `demo.sh` in P1.M2 slice 3 (see docs/ROADMAP.md). The interfaces above are the contract.

## git-hooks/

Committed local git hooks enforcing that `main`/`master` never takes a direct commit or push (CLAUDE.md repo conventions — everything goes via a `type/scope-description` branch and a PR).

- `pre-commit` — refuses `git commit` when `HEAD` is `main`/`master`.
- `pre-push`   — refuses a push whose target ref is `main`/`master`.

One-time setup per clone: `just setup-hooks` (runs `git config core.hooksPath scripts/git-hooks`). This is a local safety net, not a substitute for GitHub branch protection on `main`.
